# 非機能要件・スコープ

## 1. プロジェクトの目的と前提

- 目的: シンジケートローンを題材に、ドメイン駆動設計(DDD)とオブジェクト指向設計、テスト技法を適用した Java システム開発を、Claude Code で自動化する取り組みの実証とする。
- 本システムは学習・デモンストレーション用であり、実際の金融取引には使用しない。
- 元ネタ([ddd-ai](https://github.com/tis-abe-akira/ddd-ai))は、軽量な3層構成・JPA・インメモリ DB で実装されている。本プロジェクトは同じ業務範囲を、[docs/arch](../arch/README.md) の技術スタックで再構築する。

## 2. 対象範囲

### 対象(In scope)

FR-01〜FR-08(参加者、シンジケート、ファシリティ、ドローダウン、返済、手数料、取引照会、投資額管理)。

### 対象外(Out of scope)

- 実際の金融機関との接続、決済・送金。
- 認証・認可(元ネタは未実装)。ただし [docs/arch](../arch/README.md) で複数ユーザー分離を採る場合は再検討する。
- 為替換算(複数通貨の通算)。通貨は取引ごとの属性として保持するのみ。
- 規制・会計報告への対応。

### 将来拡張

- FR-09 レポーティング・バッチ・監査ログ
- FR-10 ファシリティ取引、複雑な配分ルール(ウォーターフォール、優先劣後)
- リスク管理(信用リスク・流動性リスク)

## 3. 非機能要件

| ID | 区分 | 要件 |
|---|---|---|
| NFR-01 | 正確性 | 金額・利率の計算は丸め誤差を生じさせない。配分結果の合計は元の金額と一致する。 |
| NFR-02 | 整合性 | 複数の更新を伴う業務操作は単一トランザクションで完結し、失敗時は部分的な更新を残さない。同時更新は楽観的排他制御で検出する。 |
| NFR-03 | 監査性 | 主要データに作成・更新日時を持たせ、全取引を追跡できる。状態遷移の履歴を追える。 |
| NFR-04 | 保守性 | 業務ルールはドメイン層に集約し、検証・計算・状態遷移を単体でテストできる。 |
| NFR-05 | テスト容易性 | 外部依存(DB 等)に頼らない単体テストを厚く書き、永続化の振る舞いはリポジトリ単位の契約テストで保証する。 |
| NFR-06 | API | REST API とし、OpenAPI で仕様を公開する。エラーは統一形式で返す。 |
| NFR-07 | 運用 | 単一インスタンス構成を前提とし、ステートレスに作る。 |
| NFR-08 | 性能 | 特定の数値目標は設けない。ただし N+1 クエリや大量データのメモリ展開を避ける。 |

## 要確認

- 利用者の想定(単一ユーザーか、複数の組織・ユーザーか)。データ分離やログインの要否に関わる。
- 永続化したデータの保持期間、バックアップ要件。
- 性能の目標値(同時利用数、データ量)。
