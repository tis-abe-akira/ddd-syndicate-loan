# Use Case: 稟議を承認する

## Overview

**Use Case ID:** UC-026  
**Use Case Name:** 稟議を承認する  
**Primary Actor:** 承認者  
**Goal:** 承認中の稟議について、自分の段の判断(承認・差し戻し・否決)を記録し、最終決裁で承認されたら稟議を承認済にして、報告先と業務に伝える  
**Trigger:** 承認者が、承認の依頼のお知らせを受けて、稟議を開く  
**Status:** Approved  

**Requirements:** [FR-025, FR-026, FR-030, NFR-003, NFR-007, NFR-009, NFR-010](../requirements.md)

## Preconditions

- 承認者がログインしていて、業務ユーザーのロールを持つ。
- 稟議が申請されている(UC-024)。

## Main Success Scenario

1. 承認者が、自分宛ての承認の依頼から、稟議を開く。
2. システムが、件名、本文、起案者、経路属性、稟議の条件と、承認経路の各段とその判断(合議先の判断とコメントを含む)を示す。
3. 承認者が、承認、差し戻し、否決のいずれかを選び、コメントを入力する。
4. 承認者が、判断を確定する。
5. システムが、判断が業務ルールを満たすことを確かめる。
6. システムが、承認者の判断とコメントと日時を記録する。
7. システムが、承認者の段が最終決裁でなければ、メイントラックの次の段の承認者に承認の依頼のお知らせを届ける。最終決裁であれば、稟議を承認済にして判断の日時を記録し、報告先の全員に報告のお知らせを、起案者に承認のお知らせを届け、稟議を起案した業務に承認を伝える。
8. システムが、記録した判断と稟議の状態を示す。

## Alternative Flows

### A1: 稟議が見つからない

**Trigger:** 稟議が存在しないか、承認者の利用組織の稟議でない (step 1)  
**Flow:**

1. システムが、稟議が見つからないことを示す。
2. Use case ends.

### A2: 今は判断できない

**Trigger:** 稟議が承認中でないか、承認者が今の回のメイントラックの段にいないか、自分の段より前の段がまだ承認していないか、承認者がその段をすでに判断した (step 2)  
**Flow:**

1. システムが、稟議とその状態を示し、今は判断できないことと、その理由を示す。
2. Use case ends.

### A3: 承認者が差し戻す

**Trigger:** 承認者が差し戻しを選んだ (step 6)  
**Flow:**

1. システムが、差し戻しとコメントと日時を記録し、同じ回のまだ判断していない段を飛ばす。
2. システムが、稟議を起案者に戻し(差し戻された状態)、起案者に差し戻しのお知らせを届け、稟議を起案した業務に差し戻しを伝える。
3. システムが、記録した判断と稟議の状態を示す。
4. Use case ends.

### A4: 承認者が否決する

**Trigger:** 承認者が否決を選んだ (step 6)  
**Flow:**

1. システムが、否決とコメントと日時を記録し、同じ回のまだ判断していない段を飛ばす。
2. システムが、稟議を否決にして判断の日時を記録し、起案者に否決のお知らせを届け、稟議を起案した業務に否決を伝える。
3. システムが、記録した判断と稟議の状態を示す。
4. Use case ends.

### A5: コメントがない

**Trigger:** 差し戻しか否決を選んだのに、コメントが空である (step 5)  
**Flow:**

1. システムが、差し戻しと否決にはコメントが要ることを示す。
2. Use case continues at step 3.

### A6: 判断の間に稟議が変わった

**Trigger:** 稟議を開いた後、判断を記録するまでの間に、別の操作で、稟議が承認中でなくなったか、承認者の段が判断されたか、差し戻された稟議が再申請されて申請の回が変わった(UC-028) (step 6)  
**Flow:**

1. システムが、判断を記録せず、別の操作で稟議が変わったことを示す。
2. Use case continues at step 2.

### A7: 承認者が判断をやめる

**Trigger:** 承認者が、判断を確定せずにやめる (step 4)  
**Flow:**

1. システムが、入力を破棄する。
2. Use case ends.

### A8: 業務が承認の結果を処理できない

**Trigger:** 最終決裁の承認を伝えた業務が、その結果を処理できない(たとえば、ファシリティを確定できない) (step 7)  
**Flow:**

1. システムが、判断を記録せず、稟議を承認中のままにし、業務が処理できない理由を示す。
2. Use case ends.

## Postconditions

### Success Postconditions

- 承認者の判断(承認)とコメントと日時が、今の回のメイントラックの段に記録されている。
- 最終決裁でなければ、稟議は承認中のままで、次の段の承認者に承認の依頼のお知らせが届いている。
- 最終決裁なら、稟議は承認済で判断の日時が記録され、報告先の段は報告済で、報告先の全員と起案者にお知らせが届き、業務に承認が伝わっている。
- 差し戻しなら(A3)、稟議は差し戻された状態で、同じ回のまだ判断していない段は飛ばされ、起案者にお知らせが届き、業務に差し戻しが伝わっている。
- 否決なら(A4)、稟議は否決で、判断の日時が記録され、同じ回のまだ判断していない段は飛ばされ、起案者にお知らせが届き、業務に否決が伝わっている。

### Failure Postconditions

- 判断は記録されず、稟議の状態と、承認経路の他の段は変わらない。
- 判断と稟議の状態とお知らせと業務への伝達のどれか一部だけが起きることはない。
- 他社の稟議は、存在するかどうかも分からない。

## Business Rules

### BR-001: 下から上へ順に

メイントラックの承認者は、段の順に判断する。自分の段より前の段がすべて承認するまで、判断できない。

### BR-002: 最終決裁で承認済

メイントラックの最後の段(最終決裁)の承認者が承認したら、稟議は承認済になる。報告先の段は報告済になる。

### BR-003: 差し戻しは振り出しに戻る

承認者が差し戻すと、稟議は起案者に戻る(差し戻された状態)。同じ回のまだ判断していない段は飛ばす。起案者は直して再申請でき、再申請では合議からやり直す(UC-028)。

### BR-004: 否決は終わり

承認者が否決すると、稟議は否決で終わり、再申請できない。条件を変えた再起案だけができる(UC-029)。同じ回のまだ判断していない段は飛ばす。

### BR-005: 差し戻しと否決にはコメントが要る

承認者の判断にも、UC-025 BR-005 を当てはめる。

### BR-006: 判断は一度

承認者の段にも、UC-025 BR-006 を当てはめる。

### BR-007: 判断できるのは段の本人だけ

段の判断ができるのは、その段の利用者本人だけである。代理の判断と、上位者が下位の段を飛ばす判断はしない。

### BR-008: 結果を業務に伝える

最終決裁の承認、差し戻し、否決は、稟議の種類と稟議の対象とともに、稟議を起案した業務に伝える。業務での処理(たとえばファシリティを確定する、UC-015 BR-006)は、業務のユースケースが決める(NFR-010)。

### BR-009: お知らせ

最終決裁でない承認では次の段の承認者に、最終決裁の承認では報告先の全員と起案者に、差し戻しと否決では起案者に、お知らせを届ける。

### BR-010: 判断の記録

承認者の判断も、UC-025 BR-010 のとおりに記録する。
