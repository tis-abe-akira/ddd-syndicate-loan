# Use Case: ドローダウンを実行する

## Overview

**Use Case ID:** UC-018  
**Use Case Name:** ドローダウンを実行する  
**Primary Actor:** リード銀行の担当者  
**Goal:** 出資者の拠出の回答がそろったドローダウンを実行し、ローンのシェアパイに拠出を加えて、返済予定表を作る  
**Trigger:** リード銀行の担当者が、拠出の回答がそろったお知らせを受けて、ドローダウンの実行を始める  
**Status:** Draft  

**Requirements:** [FR-013, FR-014, NFR-001, NFR-002, NFR-003, C-005](../requirements.md)

## Preconditions

- リード銀行の担当者がログインしていて、その融資案件のリード銀行に属している。
- ファシリティに、依頼中のドローダウンがある(UC-016)。

## Main Success Scenario

1. リード銀行の担当者が、依頼中のドローダウンの実行を始める。
2. システムが、各出資者の確定した拠出額と、その合計を示す。
3. 担当者が、実行を確定する。
4. システムが、実行が業務ルールを満たすことを確かめる。
5. システムが、ファシリティにまだローンがなければローンを作り、ローンのシェアパイに各出資者の拠出額を足す。
6. システムが、ドローダウンの返済方法、返済期間、年利から、返済予定表を作る。
7. システムが、ドローダウンを実行済みとし、借り手と各出資者にお知らせを届ける。
8. システムが、実行後のローンのシェアパイと、返済予定表を示す。

## Alternative Flows

### A1: 未確定の回答がある

**Trigger:** 拠出の回答がまだ確定していない出資者がいる (step 4)  
**Flow:**

1. システムが、回答が確定していない出資者を示す。
2. Use case ends.

### A2: 拠出の合計が足りず、依頼額を指定し直す

**Trigger:** 確定した拠出額の合計が、引き出す額に満たない (step 4)  
**Flow:**

1. システムが、足りない額を示す。
2. 担当者が、他の出資者の拠出の依頼額を、それぞれの拠出の余地の範囲で増やすよう指定し直す。
3. システムが、依頼額を変えた出資者の回答を未回答に戻し、その出資者に拠出の依頼をお知らせで届ける。
4. Use case ends.

### A3: 拠出の合計が足りず、ドローダウンを取り消す

**Trigger:** 確定した拠出額の合計が引き出す額に満たず、担当者が取り消しを選ぶ (step 4)  
**Flow:**

1. システムが、ドローダウンを取り消し済みとし、各出資者にお知らせを届ける。
2. Use case ends.

### A4: 実行日ではない

**Trigger:** 今日が、ドローダウンの実行日ではない (step 4)  
**Flow:**

1. システムが、実行日を示し、実行日の当日に実行できることを示す。
2. Use case ends.

### A5: 実行の間に別の操作がローンを変えた

**Trigger:** 確かめた後、実行するまでの間に、別の操作でローンのシェアパイかドローダウンが変わった (step 5)  
**Flow:**

1. システムが、ローンも返済予定表も変えず、ローンが別の操作で変わったことを示す。
2. Use case continues at step 2.

### A6: 担当者が実行をやめる

**Trigger:** 担当者が、確定せずに実行をやめる (step 3)  
**Flow:**

1. システムが、何も変えずに実行の画面を閉じる。
2. Use case ends.

## Postconditions

### Success Postconditions

- ドローダウンが実行済みである。
- ローンのシェアパイの各出資者の持分が、確定した拠出額の分だけ増えている。
- ローンの元本の残高(シェアパイの合計)が、引き出した額の分だけ増えている。
- ドローダウンの返済予定表があり、その元本の合計は引き出した額に等しい。

### Failure Postconditions

- ローンのシェアパイと元本の残高は変わらない。
- 返済予定表は作られない。
- ローンのシェアパイと返済予定表のどちらか一方だけが変わることはない。

## Business Rules

### BR-001: 実行できる条件

すべての出資者の拠出の回答が確定し、確定した拠出額の合計が引き出す額に等しいときだけ、実行できる。合計が足りないときは、担当者が依頼額を指定し直すか、ドローダウンを取り消す。

### BR-002: 実行は実行日の当日

ドローダウンは、実行日の当日に実行する。

### BR-003: ローンはファシリティに一つ

一つのファシリティのローンは一つだけである。初回のドローダウンの実行でローンを作り、2回目以降はそのローンに加える。

### BR-004: ローンのシェアパイに拠出を足す

各出資者のローンの持分に、その出資者の確定した拠出額を足す。各出資者のローンの持分は、その出資者のファシリティの持分を超えない。

### BR-005: 元利均等返済の予定表

返済方法が元利均等返済なら、月利を年利 ÷ 12 とし、毎回の支払額(元本と利息の合計)を一定にする。各回の利息は直前の元本の残りに月利を掛けて1円未満を切り捨て、元本は支払額から利息を引いた額とする。最終回の元本は、元本の残りの全額とする。

### BR-006: バレット返済の予定表

返済方法がバレット返済なら、毎回は利息だけを払い、最終回に元本の全額を払う。各回の利息は、元本に月利を掛けて1円未満を切り捨てる。

### BR-007: 返済日

返済日は、実行日から毎月の同じ日とし、その月にその日がなければ月末とする。銀行営業日でなければ、翌営業日にする(C-005)。

### BR-008: 予定表の元本の合計

一つのドローダウンの返済予定表の元本の合計は、引き出した額に1円の差もなく等しい。

### BR-009: 完済したローンへの実行

ローンが完済済みでも、ファシリティの引き出せる期間の中なら実行できる(利用可能額は回転型、UC-016 BR-001)。実行で元本の残高が0円より大きくなったら、ローンは返済中に戻る。
