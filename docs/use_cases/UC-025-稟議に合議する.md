# Use Case: 稟議に合議する

## Overview

**Use Case ID:** UC-025  
**Use Case Name:** 稟議に合議する  
**Primary Actor:** 合議先  
**Goal:** 合議中の稟議について、自分の判断(承認・差し戻し・否決)を記録し、合議先の全員が承認したら稟議をメイントラックに進める  
**Trigger:** 合議先が、合議の依頼のお知らせを受けて、稟議を開く  
**Status:** Approved  

**Requirements:** [FR-024, FR-030, NFR-003, NFR-007, NFR-009, NFR-010](../requirements.md)

## Preconditions

- 合議先がログインしていて、業務ユーザーのロールを持つ。
- 稟議が申請されている(UC-024)。

## Main Success Scenario

1. 合議先が、自分宛ての合議の依頼から、稟議を開く。
2. システムが、件名、本文、起案者、経路属性、稟議の条件と、承認経路の各段とその判断を示す。
3. 合議先が、承認、差し戻し、否決のいずれかを選び、コメントを入力する。
4. 合議先が、判断を確定する。
5. システムが、判断が業務ルールを満たすことを確かめる。
6. システムが、合議先の判断とコメントと日時を記録する。
7. システムが、今の回の合議先がまだ全員承認していなければ稟議を合議中のままにし、全員が承認していれば稟議を承認中にして、メイントラックの最初の承認者に承認の依頼のお知らせを届ける。
8. システムが、記録した判断と稟議の状態を示す。

## Alternative Flows

### A1: 稟議が見つからない

**Trigger:** 稟議が存在しないか、合議先の利用組織の稟議でない (step 1)  
**Flow:**

1. システムが、稟議が見つからないことを示す。
2. Use case ends.

### A2: 今は判断できない

**Trigger:** 稟議が合議中でないか、合議先が今の回の合議先の段にいないか、合議先がその段をすでに判断した (step 2)  
**Flow:**

1. システムが、稟議とその状態を示し、今は判断できないことと、その理由を示す。
2. Use case ends.

### A3: 合議先が差し戻す

**Trigger:** 合議先が差し戻しを選んだ (step 6)  
**Flow:**

1. システムが、差し戻しとコメントと日時を記録し、同じ回のまだ判断していない段を飛ばす。
2. システムが、稟議を起案者に戻し(差し戻された状態)、起案者に差し戻しのお知らせを届け、稟議を起案した業務に差し戻しを伝える。
3. システムが、記録した判断と稟議の状態を示す。
4. Use case ends.

### A4: 合議先が否決する

**Trigger:** 合議先が否決を選んだ (step 6)  
**Flow:**

1. システムが、否決とコメントと日時を記録し、同じ回のまだ判断していない段を飛ばす。
2. システムが、稟議を否決にして判断の日時を記録し、起案者に否決のお知らせを届け、稟議を起案した業務に否決を伝える。
3. システムが、記録した判断と稟議の状態を示す。
4. Use case ends.

### A5: コメントがない

**Trigger:** 差し戻しか否決を選んだのに、コメントが空である (step 5)  
**Flow:**

1. システムが、差し戻しと否決にはコメントが要ることを示す。
2. Use case continues at step 3.

### A6: 判断の間に稟議が変わった

**Trigger:** 稟議を開いた後、判断を記録するまでの間に、別の合議先の差し戻しか否決で稟議が合議中でなくなったか、差し戻された稟議が再申請されて申請の回が変わった(UC-028) (step 6)  
**Flow:**

1. システムが、判断を記録せず、別の操作で稟議が変わったことを示す。
2. Use case continues at step 2.

### A7: 合議先が判断をやめる

**Trigger:** 合議先が、判断を確定せずにやめる (step 4)  
**Flow:**

1. システムが、入力を破棄する。
2. Use case ends.

## Postconditions

### Success Postconditions

- 合議先の判断(承認)とコメントと日時が、今の回の合議先の段に記録されている。
- 今の回の合議先の全員が承認していれば、稟議は承認中で、メイントラックの最初の承認者に承認の依頼のお知らせが届いている。そうでなければ、稟議は合議中のままである。
- 差し戻しなら(A3)、稟議は差し戻された状態で、同じ回のまだ判断していない段は飛ばされ、起案者にお知らせが届き、業務に差し戻しが伝わっている。
- 否決なら(A4)、稟議は否決で、判断の日時が記録され、同じ回のまだ判断していない段は飛ばされ、起案者にお知らせが届き、業務に否決が伝わっている。

### Failure Postconditions

- 判断は記録されず、稟議の状態と、承認経路の他の段は変わらない。
- 判断と稟議の状態とお知らせのどれか一部だけが記録されることはない。
- 他社の稟議は、存在するかどうかも分からない。

## Business Rules

### BR-001: 合議は並行

合議先は、他の合議先の判断を待たずに、どの順でも判断できる。

### BR-002: 全員の承認でメイントラックへ

今の回の合議先の全員が承認したときだけ、稟議は承認中になり、メイントラックの最初の承認者に承認の依頼を届ける。

### BR-003: 差し戻しは振り出しに戻る

合議先が差し戻すと、稟議は起案者に戻る(差し戻された状態)。同じ回のまだ判断していない段は飛ばす。起案者は直して再申請でき、再申請では合議からやり直す(UC-028)。

### BR-004: 否決は終わり

合議先が否決すると、稟議は否決で終わり、再申請できない。条件を変えた再起案だけができる(UC-029)。同じ回のまだ判断していない段は飛ばす。

### BR-005: 差し戻しと否決にはコメントが要る

差し戻しと否決には、理由のコメントが要る。承認のコメントは任意である。

### BR-006: 判断は一度

一つの段の判断は一度だけで、記録した後は変えられない。

### BR-007: 判断できるのは段の本人だけ

段の判断ができるのは、その段の利用者本人だけである。代理の判断はしない。

### BR-008: 結果を業務に伝える

差し戻しと否決は、稟議の種類と稟議の対象とともに、稟議を起案した業務に伝える。業務での処理は、業務のユースケースが決める(NFR-010)。

### BR-009: お知らせ

差し戻しと否決では起案者に、メイントラックに進んだらメイントラックの最初の承認者に、お知らせを届ける。

### BR-010: 判断の記録

判断した利用者、判断、コメント、日時を記録する(NFR-009)。
