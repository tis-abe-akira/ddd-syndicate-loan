# Use Case: ファシリティを組成する

## Overview

**Use Case ID:** UC-015  
**Use Case Name:** ファシリティを組成する  
**Primary Actor:** リード銀行の担当者  
**Goal:** 参加を応諾した出資者の持分を合わせてファシリティを組成し、稟議にかけて、借り手が引き出せるコミットメント額と各出資者の持分を確定させる  
**Trigger:** リード銀行の担当者が、シンジケートへの参加の回答がそろったことを受けて、ファシリティの組成を始める  
**Status:** Draft  

**Requirements:** [FR-012, FR-023, NFR-001, NFR-002, NFR-003, NFR-007, C-012](../requirements.md)

## Preconditions

- リード銀行の担当者がログインしていて、その融資案件のリード銀行に属している。
- 融資案件が、シンジケートへの呼びかけを終えている(UC-012)。

## Main Success Scenario

1. リード銀行の担当者が、融資案件のファシリティの組成を始める。
2. システムが、参加を応諾した出資者と、それぞれが応諾したコミットメント額、その合計を示す。
3. 担当者が、引き出せる期間の初日と末日を入力する。
4. 担当者が、組成を確定する。
5. システムが、組成が業務ルールを満たすことを確かめる。
6. システムが、ファシリティを組成中として登録し、各出資者の持分を応諾したコミットメント額としてファシリティのシェアパイを作る。
7. 担当者が、組成の稟議を起案する(UC-024)。
8. システムが、ファシリティが稟議にかかっていることを示す。

## Alternative Flows

### A1: 参加を応諾した出資者がいない

**Trigger:** 参加を応諾した出資者が一社もいない (step 2)  
**Flow:**

1. システムが、組成できる出資者がいないことを示す。
2. Use case ends.

### A2: 融資案件にファシリティがすでにある

**Trigger:** その融資案件に、組成中か FIXED のファシリティがすでにある (step 2)  
**Flow:**

1. システムが、すでにあるファシリティとその状態を示す。
2. Use case ends.

### A3: 引き出せる期間が正しくない

**Trigger:** 期間の初日か末日が空であるか、末日が初日より後でないか、初日が今日より前である (step 5)  
**Flow:**

1. システムが、直すべき日付を示す。
2. Use case continues at step 3.

### A4: 組成の間に参加の回答が変わった

**Trigger:** 確かめた後、登録するまでの間に、別の操作で出資者の参加の状態かコミットメント額が変わった (step 6)  
**Flow:**

1. システムが、ファシリティを登録せず、参加の回答が変わったことを示す。
2. Use case continues at step 2.

### A5: 担当者が組成をやめる

**Trigger:** 担当者が、確定せずに組成をやめる (step 4)  
**Flow:**

1. システムが、入力を破棄する。
2. Use case ends.

### A6: 担当者が稟議を起案せずに終える

**Trigger:** 担当者が、組成の稟議を起案せずに作業を終える (step 7)  
**Flow:**

1. システムが、ファシリティを組成中のまま残す。担当者は後で稟議を起案できる。
2. Use case ends.

## Postconditions

### Success Postconditions

- ファシリティが組成中として登録され、そのシェアパイは参加を応諾した各出資者のコミットメント額からなる。
- ファシリティのコミットメント額は、シェアパイの合計に等しい。
- 組成の稟議が申請されている。

### Failure Postconditions

- ファシリティは FIXED にならない。
- すでにあるファシリティと、出資者の参加の回答は変わらない。

## Business Rules

### BR-001: 持分は応諾した出資者だけ

ファシリティのシェアパイに入るのは、その融資案件への参加を応諾した出資者だけで、各出資者の持分は、応諾したコミットメント額に等しい。

### BR-002: コミットメント額は持分の合計

ファシリティのコミットメント額は、ファシリティのシェアパイの合計に、1円の差もなく等しい。

### BR-003: 引き出せる期間

引き出せる期間の初日は今日以降で、末日は初日より後である。

### BR-004: 融資案件に一つのファシリティ

一つの融資案件のファシリティは一つだけである。

### BR-005: 組成の稟議に渡す値

組成の稟議には、経路属性としてコミットメント額(amount)と借り手のクレジットスコア(credit_score)を渡し、否決後の再起案の判定に使う条件として、通貨、引き出せる期間、各出資者の持分を渡す。

### BR-006: 承認でファシリティを確定する

組成の稟議が最終決裁で承認されたら、ファシリティは FIXED になる。FIXED のファシリティの持分、コミットメント額、引き出せる期間は変えられない。否決されたら、ファシリティは組成中のまま残る。

### BR-007: 稟議の間は変えない

組成の稟議が合議中か承認中の間は、ファシリティの持分と引き出せる期間を変えられない。

### BR-008: 通貨

ファシリティの通貨は融資案件の通貨とし、為替換算はしない。
